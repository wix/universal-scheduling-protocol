The Problem

Why USP?

Existing scheduling standards — iCalendar, CalDAV, schema.org/Service — are fragmented, lack native payment integration, and were never designed for autonomous AI agents.

Principles

Design Principles

Built from the ground up for the agentic commerce era.

Interoperable

Two deployment modes (UCP-Native for existing UCP platforms, Standalone for self-contained scheduling) share the same domain core and transport bindings.

Agent-First

Every operation is designed for programmatic consumption. AI agents autonomously discover, evaluate, and book services with continue_url handoff when human input is needed.

Secure & Private

OAuth 2.0 identity linking, HTTP Message Signatures for webhooks, structured buyer consent, and TLS 1.3 transport.

Open & Extensible

Apache 2.0 licensed. Vendor extensions via reverse-domain namespaces (e.g., com.wix.services.courses). JSON Schema composition for custom capabilities.

Workflow

How It Works

Three capabilities power the complete scheduling journey.

1

Discover

Browse the service catalog — types, pricing, policies, resources, and locations.

POST /services/list
2

Check Availability

Query time slots, hold a slot to prevent double-booking during checkout.

POST /availability/query
3

Book

Create the booking, manage the lifecycle — confirm, reschedule, cancel.

POST /bookings

Architecture

Two Deployment Modes, One Protocol

Choose the mode that fits your infrastructure. Both share the same scheduling core.

UCP-Native Mode

For platforms that already support the Universal Commerce Protocol. Scheduling capabilities register directly in /.well-known/ucp.

  • Atomic checkout (booking + payment in one call)
  • Inherits UCP infrastructure (auth, errors, webhooks)
  • Single profile at /.well-known/ucp
Learn more →

Standalone Mode

Self-contained scheduling protocol. Businesses publish /.well-known/usp. Payment uses a generic payment_context that works with any checkout system.

  • Works with any payment system
  • ACP extension available for structured checkout
  • IETF-native infrastructure (OAuth 2.0, RFC 9457)
Learn more →

Transports

Transport Bindings

USP is transport-agnostic. Implement using the binding that fits your architecture.

REST

HTTP/OpenAPI 3.x with idempotency keys. The primary transport.

MCP

JSON-RPC for AI agent tool use via the Model Context Protocol.

A2A

Agent-to-Agent protocol for autonomous multi-agent interactions.

ESP

Embedded Scheduling Protocol for in-app booking UIs via iframe.
